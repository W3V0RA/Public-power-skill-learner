# Personalized learning interview

This interview is **for the person copying the repository**. Do not assume a particular employer, venture, personal identity, financial position, or geography. Ask conversationally, one or two questions at a time, and allow “skip”. Save responses only with the learner's consent and in private storage.

1. **Outcome:** What would you like AI to help you accomplish over the next 30–90 days? What measurable change would matter?
2. **Project:** Which ONE real project can serve as your practice sandbox? Can you describe it without disclosing private customer information?
3. **Background:** How comfortable are you with programming, databases, Git, and AI tools? Beginner, intermediate, or advanced?
4. **Domain:** What type of work interests you? Operations, engineering, research, writing, analytics, design, education, or something else?
5. **Tools:** What is already available? Assistant, spreadsheet, GitHub, code editor, database, automation tool, browser access?
6. **Time:** How many minutes can you realistically practice per session? What cadence fits your week?
7. **Budget:** Free-only, existing subscriptions, or a capped amount you explicitly authorize?
8. **Autonomy:** Should application remain simulation-only, draft-only, or allow bounded writes to a named project? What always requires approval?
9. **Privacy:** Which inputs, files, organizations, accounts, or actions must never appear in a public report or be sent to another provider?
10. **Evidence:** How can you tell a real improvement occurred? Examples: fewer verified errors, reduced elapsed time, more completed tasks, lower cost per verified outcome.
11. **Retention:** Do you prefer short recall questions, debugging exercises, building something, or weekly capstones?
12. **Accessibility:** Any language, format or time constraints the lessons should respect?

## Interview handoff contract

Return a private learner profile; three to five prioritized skills; the first small dry-run exercise; a measurement plan; and the exact approval boundary. Do not create scheduled tasks, connect accounts, or write to a project until requested. Never require a person to reveal sensitive information to use this public educational skill.

For an offline implementation, run `python3 scripts/interview.py` instead of sharing answers online.
